    What this tool does, and what it refuses to do

    Disclosure Ledger checks one deliverable against the AI-disclosure rules you select, and hands you three things: a gap list with the rule and the wording to use, a disclosure statement draft, and a hash-chained record of every step.

    It decides nothing by guessing. A clause applies only when a signal is true — declared by you, or found as a literal term in the text — and it counts as satisfied only when one of its phrase patterns really occurs in the deliverable. If nothing matches, you get a gap, not a reassuring silence.

    It does not do legal advice. The rule packs are short paraphrases written by hand, with the source named and the clause number kept. Read the source before you rely on it.

    It does not upload anything. There is no server, no API key, no analytics and no font or script from a CDN. You can open this page, switch off the network, and it still works.

    How the ledger works

    record[n].hash = SHA-256( record[n-1].hash + "\n" + canonical({seq, timestamp, type, payload}) )
record[0].prevHash = 0000…0000 (64 zeros)

    Canonical means JSON with the object keys sorted and no insignificant whitespace, so the same record hashes identically in JavaScript and in Python. Verify the chain here, in the exported HTML file, or from the command line:

    python3 tools/verify_ledger.py ledger.json

    Editing a record, reordering records, or dropping one from the middle is detected; the verifier reports the first index where the chain stops matching.

    Where the data lives

    your text ──▶ FileReader / textarea ──▶ analysis in the page
                    │
                    ├─▶ IndexedDB (or localStorage): recent documents, answers, ledger
                    ├─▶ .json / .html / .md download  ← the only way data leaves
                    └─▶ SHA-256 (WebCrypto) → hash chain

    Clearing site data, or pressing Clear on the ledger tab, removes it. Exports are ordinary files you decide what to do with.
